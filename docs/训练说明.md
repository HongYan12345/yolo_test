# 冒险岛识图模型训练说明

本项目训练目标是一个六类 YOLO 目标检测模型，类别顺序与当前 Roboflow 下载数据中的 `data.yaml` 对齐：

```text
0: Item       # 掉落物/道具
1: Mob        # 怪物
2: Platform   # 平台/可站立地形
3: Player     # 玩家角色
4: Portal     # 传送门
5: Rope       # 绳索/梯子
```

注意：YOLO 类别编号必须从 `0` 开始。标注工具中建议直接使用英文类别名 `Item/Mob/Platform/Player/Portal/Rope`，并确保导出的 `data.yaml` 类别顺序与上面一致。

模型输入为游戏截图或截图区域，输出掉落物、怪物、平台、玩家、传送门和绳索的边界框、类别和置信度。

## 0. 新电脑拉取后能不能直接运行？

结论：**可以直接双击/运行 `.cmd` 启动流程，但如果另一台电脑上还没有放入背景截图、真实截图和真实标签，训练不会真正开始，会在数据检查阶段停止。**

当前 `冒险岛` 分支已经包含：

```text
assets/monsters/raw/       # 已爬取怪物 PNG 素材
assets/items/raw/          # 已爬取物品/掉落物 PNG 素材
assets/monsters/metadata.csv
assets/items/metadata.csv

run_train_auto.cmd
run_train_1080.cmd
train_auto.ps1
train_1080.ps1
requirements-train.txt
tools/
docs/
datasets/                  # 只包含目录骨架和 .gitkeep
```

当前分支**没有也不建议直接提交**以下本地训练数据：

```text
datasets/backgrounds/      # 空地图/少目标背景截图
datasets/real/images/      # 真实游戏截图
datasets/real/labels/      # 真实截图 YOLO 标签
datasets/synthetic/        # 脚本生成的合成数据
datasets/yolo/             # 脚本生成的 YOLO 数据集
runs/                      # 训练输出
*.pt / *.onnx              # 权重和导出模型
```

所以另一台电脑首次拉取后，正确顺序是：

```powershell
git clone <你的仓库地址>
cd MapleStoryAI
git checkout 冒险岛

# 1. 放入背景截图
#    datasets/backgrounds/*.png 或 *.jpg

# 2. 放入真实截图
#    datasets/real/images/*.png 或 *.jpg

# 3. 放入真实截图对应 YOLO 标签
#    datasets/real/labels/*.txt

# 4. 再运行一键训练
.\run_train_auto.cmd
```

如果是 GTX 1080 那台电脑，也可以运行：

```powershell
.\run_train_1080.cmd
```

首次运行 `.cmd` 会自动做这些事：

1. 创建 `.venv` 虚拟环境。
2. 安装/检查 PyTorch、Ultralytics、OpenCV、Pillow 等依赖。
3. 检查 `assets/monsters/raw/` 和 `assets/items/raw/` 是否存在素材。
4. 检查 `datasets/backgrounds/` 是否已有背景截图。
5. 检查 `datasets/real/images/` 是否已有真实截图。
6. 检查每张真实截图是否都有同名 `.txt` 标签。
7. 生成 `datasets/synthetic/`。
8. 生成 `datasets/yolo/`。
9. 开始 YOLO 训练。
10. 导出 ONNX。

如果只想确认环境和数据是否齐全，可以运行：

```powershell
.\run_train_auto.cmd -NoTrain
```

注意：`-NoTrain` 也会执行依赖安装、输入检查、合成数据生成和 YOLO 数据集构建，只是不进入最终训练阶段。

## 1. GTX 1080 电脑上一键训练

本仓库已经准备了两套 Windows 一键训练入口：

```text
run_train_auto.cmd      # 通用入口：当前笔记本/其他电脑优先用这个
train_auto.ps1          # 通用入口的 PowerShell 主脚本

run_train_1080.cmd      # GTX 1080 专用入口
train_1080.ps1          # GTX 1080 专用 PowerShell 主脚本
```

### 1.1 当前笔记本/其他电脑推荐入口

如果不是固定使用 GTX 1080 那台电脑，推荐使用通用入口：

```powershell
git clone <你的仓库地址>
cd MapleStoryAI
.\run_train_auto.cmd
```

或者直接双击：

```text
run_train_auto.cmd
```

通用入口会自动检测当前电脑：

- 如果检测到 NVIDIA GPU，会优先使用 GPU 训练。
- 如果检测不到 NVIDIA GPU，会自动切到 CPU 流程。
- 如果是 GTX 10 系、老 Quadro/Tesla，会默认选择 CUDA 11.8 PyTorch wheel。
- 如果是较新的 NVIDIA 显卡且驱动满足要求，会优先选择 CUDA 12.1 PyTorch wheel。
- 如果显存低于约 7GB，默认 batch 会自动降到 4。
- 如果没有手动指定 `ImageSize`，GPU 默认用 640，CPU 默认用 512。

通用入口常用命令：

```powershell
# 自动检测电脑配置并训练
.\run_train_auto.cmd

# 当前电脑没有合适 GPU，强制 CPU 跑通流程
.\run_train_auto.cmd -Cpu

# 只检查环境和数据，不开始训练
.\run_train_auto.cmd -NoTrain

# 低显存电脑手动降低 batch
.\run_train_auto.cmd -Batch 4

# CPU 或低性能电脑降低图片尺寸
.\run_train_auto.cmd -Cpu -ImageSize 512 -Batch 4

# 重新生成合成数据和 YOLO 数据集
.\run_train_auto.cmd -RebuildSynthetic -RebuildYolo
```

### 1.2 GTX 1080 专用入口

在 GTX 1080 电脑上，也可以继续使用 1080 专用入口：

```powershell
git clone <你的仓库地址>
cd MapleStoryAI
.\run_train_1080.cmd
```

或者直接双击：

```text
run_train_1080.cmd
```

1080 专用入口默认使用 CUDA 11.8 PyTorch wheel，参数更偏向 GTX 1080。

这些入口会自动执行：

1. 创建 `.venv` 虚拟环境。
2. 优先使用 Python 3.11，其次 Python 3.10，再其次系统默认 Python。
3. 安装 CUDA 版 PyTorch。
4. 安装 `requirements-train.txt` 中的训练依赖。
5. 检查 `assets/monsters/raw/` 和 `assets/items/raw/` 是否存在素材。
6. 检查 `datasets/backgrounds/` 是否已有背景截图。
7. 检查 `datasets/real/images/` 是否已有真实截图。
8. 生成 `datasets/synthetic/` 合成训练集。
9. 生成 `datasets/yolo/data.yaml`。
10. 使用 YOLOv8n 开始训练。
11. 训练完成后导出 ONNX。

默认训练配置：

```text
model      = yolov8n.pt
imgsz      = 640
epochs     = 100
batch      = 8
workers    = 4
device     = 0
amp        = False
flipud     = 0
```

如果 GTX 1080 显存不够，可以运行：

```powershell
.\run_train_1080.cmd -Batch 4
```

如果只想检查环境和数据集，不想立刻训练：

```powershell
.\run_train_1080.cmd -NoTrain
```

如果要重新生成合成数据和 YOLO 数据集：

```powershell
.\run_train_1080.cmd -RebuildSynthetic -RebuildYolo
```

如果 CUDA 环境暂时装不好，可以 CPU 兜底测试流程：

```powershell
.\run_train_1080.cmd -Cpu -Batch 4 -ImageSize 512
```

注意：即使一键脚本已经准备好，训练前仍然必须有以下人工数据：

```text
datasets/backgrounds/      # 空地图/少目标背景截图，不需要标注
datasets/real/images/      # 真实游戏截图，需要人工标注
datasets/real/labels/      # 真实截图 YOLO 标签
```

标注结论：

- `assets/monsters/raw/`、`assets/items/raw/`：爬虫素材，不需要你手工标注。
- `datasets/backgrounds/`：背景截图，不需要标注。
- `datasets/synthetic/`：合成图由脚本自动生成 `Item/Mob` 标签，即 `0/1`，不自动生成 `Platform/Player/Portal/Rope`。
- `datasets/real/images/`：真实游戏截图必须人工标注。
- 如果真实截图里有 `Item/Mob/Platform/Player/Portal/Rope` 任一目标，必须在对应 `.txt` 里写 YOLO 框。
- 如果真实截图里没有这六类目标，也必须放一个同名空 `.txt`，表示负样本。
- 如果真实截图缺少对应 `.txt`，脚本会停止，避免把“没标注的有目标图片”误当成“无目标负样本”。

如果这些目录为空，或者真实截图缺少对应标签文件，脚本会停止并提示需要补充数据。

## 2. Roboflow Classic MapleStory 可以直接用吗？

你找到的 Roboflow Universe 数据集/模型可以用来参考，但不建议无脑作为最终数据源。当前更推荐的路线是：**自己截真实游戏画面，自己标注，再本地训练**。

原因：

1. Roboflow Universe 上的公开版本可能已经固定 preprocessing，下载图片可能不是原始游戏比例。
2. 已确认有版本使用：
   ```text
   Auto-Orient: Applied
   Resize: Stretch to 640x640
   ```
   这会把 16:9 游戏截图强行拉成 1:1，怪物、人物、平台、绳索都会变形。
3. 页面预览看到的图片比例不一定等于下载后的图片比例；下载结果取决于该 Dataset Version 的 preprocessing。
4. 公开数据的地图、怪物、UI、技能特效、分辨率可能与你真实运行环境不一致。
5. Roboflow 免费版/公开数据在项目数量、图片数量、训练、私有数据、版本管理等方面可能有额度或收费限制。

当前项目类别顺序为：

```text
0 Item
1 Mob
2 Platform
3 Player
4 Portal
5 Rope
```

推荐策略：

- 公开 Roboflow 数据可以作为参考或冷启动补充。
- 最终验证集和测试集必须尽量使用你自己的真实游戏截图。
- 如果公开版本只能下载到 `Stretch to 640x640` 的数据，不建议作为主训练集。
- 如果已经下载了 Stretch 版，可以用导入脚本的 `--restore-aspect 16:9` 作为补救，但最佳方案仍然是拿原始比例截图自己标注。

### 2.1 下载 Roboflow 数据集后放哪里？

建议手动从浏览器打开：

```text
https://universe.roboflow.com/maplestory-object-detection/classic-maplestory
```

下载 YOLOv8 或 YOLOv5 格式，解压到：

```text
datasets/external/classic-maplestory/
```

典型目录应该类似：

```text
datasets/external/classic-maplestory/
  data.yaml
  train/
    images/
    labels/
  valid/
    images/
    labels/
  test/
    images/
    labels/
```

`datasets/external/` 已加入 `.gitignore`，下载的大量截图不会被误提交。

### 2.2 导入到本项目真实数据集

我新增了导入脚本：

```text
tools/import_roboflow_yolo.py
```

它会读取 Roboflow 的 `data.yaml`，按类别名把外部标签映射到本项目六类：

```text
Item      -> 0
Mob       -> 1
Platform  -> 2
Player    -> 3
Portal    -> 4
Rope      -> 5
```

常用命令：

```powershell
python tools/import_roboflow_yolo.py `
  --source-dir datasets/external/classic-maplestory `
  --output-real-dir datasets/real `
  --prefix roboflow_classic
```

如果 Roboflow 的类别名不是标准的 `Item/Mob/Platform/Player/Portal/Rope`，可以手动映射。例如它叫 `Enemy`、`Drop`、`Ladder`：

```powershell
python tools/import_roboflow_yolo.py `
  --source-dir datasets/external/classic-maplestory `
  --output-real-dir datasets/real `
  --prefix roboflow_classic `
  --map Enemy=mob `
  --map Drop=item `
  --map Ladder=rope `
  --map Character=player
```

如果只想保留含目标类别的图片，丢弃导入后没有目标框的图片：

```powershell
python tools/import_roboflow_yolo.py `
  --source-dir datasets/external/classic-maplestory `
  --output-real-dir datasets/real `
  --prefix roboflow_classic `
  --drop-empty
```

如果下载的 Roboflow 图片已经被强行 Stretch 成 `640x640`，可以临时恢复到 16:9 再导入：

```powershell
python tools/import_roboflow_yolo.py `
  --source-dir datasets/external/classic-maplestory `
  --output-real-dir datasets/real `
  --prefix roboflow_classic `
  --clean `
  --restore-aspect 16:9
```

注意：`--restore-aspect 16:9` 是补救方案。它可以把 `640x640` 拉回例如 `640x360`，YOLO 归一化标签仍然能对应整张图，但图像细节已经被 Roboflow 预处理破坏过一次，不如原始 16:9 截图。

导入完成后，再重建 YOLO 数据集并训练：

```powershell
.\run_train_auto.cmd -RebuildYolo
```

GTX 1080 电脑：

```powershell
.\run_train_1080.cmd -RebuildYolo
```

### 2.3 能不能直接下载它的模型来用？

可以尝试，但只适合快速验证，不建议作为最终方案直接上脚本。

只有满足这些条件时，才适合直接使用或微调：

- 能拿到 YOLO/Ultralytics 可用的 `.pt` 权重。
- 它的类别和本项目一致，或者你愿意把脚本目标改成它的类别。
- 它能识别你真正需要的 `Mob/Item/Platform/Player/Rope`。
- 在你自己的游戏截图上测试过漏检和误检。

如果拿到了可用 `.pt` 权重，可以放到：

```text
models/classic_maplestory.pt
```

然后作为训练起点微调：

```powershell
.\run_train_auto.cmd -Model models/classic_maplestory.pt -RebuildYolo
```

但如果它的类别数不是 6，Ultralytics 会重建检测头，预训练只能部分复用，仍需要用本项目六类数据重新训练/微调。

## 3. 自己截图标注的推荐路线

当前更推荐使用本地免费标注流程，不依赖 Roboflow 收费服务或公开版本 preprocessing：

```text
自己截图 -> 自己标注 -> 导出 YOLO -> 放入 datasets/real -> 本地训练 YOLO
```

推荐标注工具：

```text
CVAT        # 最推荐，适合长期维护数据集，支持 YOLO 导出
LabelImg    # 本地免费，适合快速标 100~300 张图
Label Studio# 功能强，但配置相对复杂
```

### 3.1 起步数据量建议

不要一开始追求一次性标完全部类别。建议分阶段：

```text
v1：100~200 张，优先标 Item / Mob / Player / Portal
v2：补到 300~500 张，增加更多地图、怪物、掉落物和负样本
v3：补 Platform / Rope
v4：根据模型漏检/误检截图继续补标
```

更稳定的数据量：

```text
300~800 张：通常开始可用
1000+ 张：识别稳定性更好
```

比图片数量更重要的是每类框的数量。建议逐步达到：

```text
Item      300+ 个框
Mob       300+ 个框
Platform  300+ 个框
Player    200+ 个框
Portal    100+ 个框
Rope      200+ 个框
```

### 3.2 截图建议

截图应尽量覆盖真实运行环境：

```text
不同地图
不同怪物
不同背景亮度
人物站立、移动、跳跃
物品掉落在不同位置
Portal 出现
怪物/物品重叠
技能特效遮挡
UI 正常显示
```

不要只截同一个地图、同一种怪物，否则模型实战泛化会差。

### 3.3 标注类别和顺序

标注工具中建议设置类别名：

```text
Item
Mob
Platform
Player
Portal
Rope
```

导出的 YOLO 类别顺序必须是：

```text
0 Item
1 Mob
2 Platform
3 Player
4 Portal
5 Rope
```

每张图片对应一个同名 `.txt` 标签文件：

```text
datasets/real/images/frame_000001.png
datasets/real/labels/frame_000001.txt
```

没有任何目标的截图也要创建空 `.txt`，表示确认这是负样本。

### 3.4 标注规则建议

```text
Item      只框掉落物/道具本体，不要框太大
Mob       框怪物可见身体，不要把血条、名字、技能特效框进去
Platform  框可站立平台/地形区域，尽量保持标注规则一致
Player    框玩家角色本体，不要包含大范围技能特效
Portal    框传送门本体
Rope      框绳索/梯子可攀爬区域
```

如果第一版只想快速验证，可以暂时少标或不标 `Platform/Rope`，先让 `Item/Mob/Player/Portal` 跑起来。

```text
datasets/backgrounds/
```

## 7. 第二步：生成合成训练图

使用脚本：

```text
tools/make_synthetic_dataset.py
```

示例命令：

```powershell
python tools/make_synthetic_dataset.py `
  --background-dir datasets/backgrounds `
  --monster-dir assets/monsters/raw `
  --item-dir assets/items/raw `
  --output-dir datasets/synthetic `
  --count 3000 `
  --seed 42
```

如果使用 cmd.exe，把反引号换成 `^`：

```cmd
python tools\make_synthetic_dataset.py ^
  --background-dir datasets\backgrounds ^
  --monster-dir assets\monsters\raw ^
  --item-dir assets\items\raw ^
  --output-dir datasets\synthetic ^
  --count 3000 ^
  --seed 42
```

输出：

```text
datasets/synthetic/images/*.jpg
datasets/synthetic/labels/*.txt
```

注意：合成图只会自动生成 `Item/Mob` 标签，类别编号分别是 `0/1`；不会自动生成 `Platform/Player/Portal/Rope` 标签。

如果你之前已经生成过旧版两类合成数据，必须重新生成：

```powershell
.\run_train_auto.cmd -RebuildSynthetic -RebuildYolo
```

或者 GTX 1080 专用入口：

```powershell
.\run_train_1080.cmd -RebuildSynthetic -RebuildYolo
```

YOLO 标签格式：

```text
class_id x_center y_center width height
```

全部坐标均为 0~1 归一化。

## 8. 第三步：准备真实截图和人工标注

真实截图放入：

```text
datasets/real/images/
```

对应标签放入：

```text
datasets/real/labels/
```

示例：

```text
datasets/real/images/frame_000001.png
datasets/real/labels/frame_000001.txt
```

如果一张图没有 `Item/Mob/Platform/Player/Portal/Rope` 这六类目标，也必须放一个空的 `.txt` 标签文件，作为负样本。不要省略这个 `.txt`，因为省略标签文件和“确认无目标”不是一回事。

推荐标注工具：

- CVAT
- Label Studio
- LabelImg
- Roboflow

标注规则：

- 掉落物标为 `0 Item`
- 怪物标为 `1 Mob`
- 平台标为 `2 Platform`
- 玩家标为 `3 Player`
- 传送门标为 `4 Portal`
- 绳索/梯子标为 `5 Rope`
- 宠物、NPC、技能特效、背景装饰默认不标注
- 严重遮挡且无法判断的目标可以不标
- 小目标 item 如果希望模型能拾取，就必须标注并保留足够样本
- 每张真实截图都必须有同名 `.txt` 标签文件
- 没有任何目标的真实截图使用空 `.txt`，作为负样本
- 不要把未标注的有目标截图当负样本，否则会显著拉低识别效果

补充说明：

- `Item/Mob` 可以通过合成图自动生成一部分标签，但真实截图里仍然建议补标。
- `Platform/Player/Portal/Rope` 目前主要依赖真实截图人工标注。
- 平台和绳索是导航目标，如果后续需要非常精确的站位/路径，YOLO 框可以先做 MVP；更精确时再考虑分割模型或额外地图结构解析。

MVP 起步建议：

```text
真实截图：100~500 张
含绳索：不少于 50~150 张
含平台：不少于 100~300 张
含怪物：不少于 100~300 张
含掉落物：不少于 100~300 张
负样本：不少于 50~100 张
```

更稳定的第一版建议：

```text
真实截图：500~1000 张
合成图：3000~10000 张
```

## 15. 常见问题

### 15.1 没有背景图时能不能训练？

不建议。没有背景图只能使用透明素材原图，域差异太大，实战效果会很差。

### 15.2 可以只用合成图训练吗？

可以用于冷启动，但不能作为最终验收。最终必须用真实截图验证和微调。

### 15.3 Item 检测差怎么办？

优先处理：

1. 增加真实地面掉落物截图。
2. 增加 Item 合成数量。
3. 调整合成尺寸，让 Item 更接近真实游戏内大小。
4. 保持 `imgsz=640`。
5. 加入角色附近 ROI 二次检测。

### 15.4 训练指标很高但实战差怎么办？

通常是验证集不真实或合成域差异太大。

解决：

1. val/test 改为真实截图。
2. 增加负样本。
3. 收集误检帧补标。
4. 降低不真实合成比例。
5. 加入实战录屏抽帧做主动学习。

### 15.5 标签文件可以为空吗？

可以，但只适用于真实无目标截图。空标签表示该图没有 `Item/Mob/Platform/Player/Portal/Rope` 六类目标，是负样本。

如果图片里有这六类任一目标，就不能用空标签，必须画框标注。

### 15.6 我到底哪些图片要标注？

需要人工标注的只有：

```text
datasets/real/images/
```

不需要人工标注的有：

```text
assets/monsters/raw/       # 爬虫怪物素材
assets/items/raw/          # 爬虫物品素材
datasets/backgrounds/      # 背景截图
datasets/synthetic/        # 合成图，Mob/Item 标签自动生成
```

真实截图标注输出放到：

```text
datasets/real/labels/
```

示例：

```text
datasets/real/images/frame_000001.png
datasets/real/labels/frame_000001.txt
```

如果 `frame_000001.png` 里有 `Item/Mob/Platform/Player/Portal/Rope` 任一目标，`frame_000001.txt` 必须写框。
如果 `frame_000001.png` 是无六类目标截图，`frame_000001.txt` 可以是空文件。
